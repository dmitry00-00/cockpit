# Приложение игрока — текущая реализация П10

Отдельная страница `/player/` и отдельный JavaScript entry. Она не запускает мастерский App/store/seed, не читает журнал кампании. Только назначенный по одноразовому приглашению герой, общая сводка партии и мирового времени. Изменение кампании игроком в эту версию не входит.

## Локальный запуск ведущего

Сгенерировать ключ в терминале перед запуском (не коммитить и не использовать префикс VITE_):

```sh
export DM_PLAYER_HOST_KEY="$(node -e 'process.stdout.write(require("node:crypto").randomBytes(32).toString("base64url"))')"
npm run dev -- --host 127.0.0.1 --port 5181
```

В ширме раскрыть «Подключение игроков», ввести тот же ключ ведущего, выбрать персонажа и создать приглашение. Ключ остаётся только в памяти вкладки ведущего; игроку отправляется только одноразовая ссылка. Приглашение действует 5 минут, подключение — 24 часа. Кнопка отзыва немедленно инвалидирует все подключения и приглашения героя на сервере; телефон очищает свою локальную копию при следующем ответе 401. Офлайн-устройство физически не может получить отзыв до восстановления связи.

Адрес 127.0.0.1 доступен только на самом компьютере. Для телефона требуется выбранный владельцем доступный HTTPS адрес и доверенный сертификат/HTTPS reverse proxy. Автоматического публичного размещения и обхода предупреждений сертификата нет. Установка PWA требует HTTPS; localhost/127.0.0.1 — исключение для разработки: [MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Сборка и офлайн

`npm run build` создаёт три entry: ширма, `/player/`, `/company-site/`. `build:player-shell` строит precache только из графа зависимостей приложения игрока, его CSS/шрифтов и установочных иконок. Service worker работает только в `/player/`, API не кэширует. Для проверки собранной версии: `npm run preview -- --host 127.0.0.1`; ключ должен оставаться в окружении процесса preview.

Без связи показывается последний разрешённый снимок с отметкой времени. В localStorage игрока хранятся `dm-cockpit:player-session:v1` (credential и DTO) и необязательная настройка интерфейсного отклика `dm-cockpit:feedback:player:v1` (звук/вибрация, выключены по умолчанию). Отклик локален, не синхронизируется с мастером, не входит в снимок игрока и не содержит данных кампании; его согласие отделено от мастерской настройки `dm-cockpit:feedback:master:v1`. При выходе/получении отзыва запись сессии удаляется; настройка отклика остаётся на устройстве. Мастер каждые 10 секунд обновляет опубликованный снимок; если heartbeat отсутствует 30 секунд, клиент перестаёт обозначать лист как живой даже при доступном relay. Перезапуск relay сбрасывает все приглашения и подключения: требуется переподключение; журнал мира не затрагивается.

## Проверки и оставшаяся приёмка

Проверки чистой проекции включают секретные sentinel-данные и отсутствие метаданных/полного журнала/чужих листов. Клиентские тесты проверяют join, polling, stale offline, очистку при 401 и выходе. Отдельные HTTP-тесты проверяют авторизацию, одноразовость, actor binding, expiry/revocation, Origin и no-store.

Ещё требуется настоящая установка на iOS/Android с HTTPS, офлайн-перезапуск установленного приложения и браузерная проверка связки ведущий→телефон. Наличие manifest и тестов не означает прохождение этих шагов. Пока не выбран адрес хостинга/сертификат, это не завершённая мобильная поставка.
