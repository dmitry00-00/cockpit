# БА27 — дальний план повышений (Luna)

## Реализация

- Добавлен чистый `campaign/levelPlan.ts`: последовательность заполненных `LevelUpChoice` рассчитывается через `previewLevelUp`, который использует существующую `levelUp`. Функции не мутируют актёра и не отправляют события.
- В `LevelUpForm` появился локальный режим «Сохранить в план». Доступное имя и заголовок отличаются от реального повышения («Решение плана для N-го уровня» / «Шаг плана»); plan-mode не получает кампанийный `onLevelUp` callback.
- `LevelPlan` даёт выбрать целевой уровень, заполняет ближайший незавершённый шаг, показывает завершённые шаги и позволяет править ранний выбор. При правке всё после него сбрасывается, поскольку основано на прежнем листе.
- При полном пути показывается расчётный лист. При неполном показывается последний полностью подтверждённый уровень и отдельный сохранённый кандидат с предупреждением. `validThrough` никогда не включает кандидата с предупреждением; такой кандидат не попадает в расчётный актёр и итоговый лист не показывается. Поздние шаги не рассчитываются. Поддержка Д8 класса по-прежнему обязательна; Изобретатель явно останавливается на причине из `levelUpPlan`.
- Сводки решений показывают названия подклассов и черт из компендиума, а не id.
- `CharacterPathView` принимает необязательный `actor`. При совпадении класса добавляет отдельный планировщик. Root интегрировал `actor={actor}` в вызов DeskPage.

## Строка интеграции в DeskPage

Вызов в `src/pages/DeskPage.tsx` (около строки 1086):

```tsx
<CharacterPathView key={`path-${actor.id}-${path.level}`} path={path} next={nextLevelText(path)} actor={actor} />
```

Существующий редактор персонажа prop не передаёт. DeskPage редактировал root.


Результат после ревью: 4 файла, 11 тестов прошли. В дополнительном прогоне после интеграции: `npx vitest run src/pages/desk/path.test.tsx src/components/LevelUpForm.test.tsx src/components/LevelPlan.test.tsx --maxWorkers=2` — 3 файла, 11 тестов прошли. Подтверждены раздельные доступные имена реальной формы и формы решения плана, сохранение выбора только в плановом callback, сохранение неполного кандидата и последнего валидного уровня, отсутствие полного итога при предупреждении, правка кандидата/раннего шага с инвалидацией зависимых поздних решений, равенство последовательным предпросмотрам Д8, отсутствие мутации исходного актора и ограничение Изобретателя.

## Ограничения и остаток БА27

- Дальние расчёты доступны только для уровней, поддержанных текущей одноступенчатой Д8; мультикласс не моделируется.
- Выборы из текста (например, боевые манёвры) намеренно не придумываются и останавливают расчёт следующих уровней. Для них нужна разметка источника/выборов и расширение модели `LevelUpChoice`.
- В текущем листе без выбранного подкласса, если выбор уже остался позади, предпросмотр честно останавливается: этот выбор нельзя автоматически восстановить будущим шагом.
- Изменение решения аннулирует все поздние шаги, без автоматического переиспользования даже совпадающих значений.
- Визуальная/браузерная приёмка не выполнялась. БА27 остаётся открытой: нужны разметка и сложные выборы, живописная графика и общая художественная приёмка.
