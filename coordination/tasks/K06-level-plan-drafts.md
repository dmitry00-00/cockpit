Нужна реализация независимым агентом Kimi в свежем snapshot batch02. Не менять DeskPage, engine, общие docs, package.json, генераторы, браузер/сервер не запускать. Выход только: src/components/LevelPlanDrafts.tsx (новый), LevelPlan.tsx, LevelUpForm.tsx, CharacterPathView.tsx и их прицельные тесты; research/coordination/K06-level-plan-drafts.md. Без commit/push. node_modules read-only.

Проблема: план повышений (цель, сохранённые решения и ещё заполняемая форма) теряется при смене вкладки листа, закрытии модалки или выборе другого персонажа. Это состояние интерфейса, не события кампании и не localStorage/global singleton.

Контракт интеграции: экспортировать LevelPlanDraftProvider из нового файла. Codex обернёт им один Desk; lifetime — одна сессия стола, новая сессия сбрасывает provider. В provider/context хранить независимые черновики по actor.id + classId + текущий уровень (и подкласс, если нужен для корректности). Разные персонажи и применённое повышение не смешиваются. Undo может вернуть сохранённый план прежнего уровня. Никакого чтения store из компонентов.

Под provider CharacterPathView/LevelPlan должны восстанавливать раскрытие планировщика, целевой уровень, подтверждённые шаги, редактируемый шаг и НЕСОХРАНЁННЫЕ значения полей формы (включая строку броска/поиск заклинаний). Обычная форма реального повышения intent=apply не получает новые действия/события. Без provider компоненты работают локально, как раньше. Возможный путь: типизированный draft и useDraft hook с optional context; LevelUpForm получает optional draft/onDraftChange для intent=plan, сохраняет локальный fallback и initialChoice для обычной формы. Избежать setState циклов/effect-синхронизации на каждый рендер.

Оставить прежнюю механику расчёта/валидации, неподтверждённые ограничения источников и удаление зависимых поздних шагов при правке раннего. При изменении actor пересчитывать результат по текущему листу, не показывать старый cached итог.

Приёмка: заполнить часть формы, размонтировать subtree и вернуть под тем же provider → поля целы; переключить actor → другой план; вернуть actor → исходный план; уровень+1 → новый план; новый provider → сброс; менять цель/ранний выбор → корректные зависимые шаги; журнальные/actor данные не меняются. Прицельный Vitest maxWorkers2 и tsc --noEmit -p tsconfig.app.json. Не full suite/build/generators. Отчёт: файлы, результаты, ограничения, пример интеграции provider для Codex. Если контракт спорный, выбрать простой корректный вариант и явно описать, не трогая общие файлы.
