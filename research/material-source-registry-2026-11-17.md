# Реестр сайтов и ресурсов игровых материалов

Срез: 17.11.2026. Назначение — собрать в одном месте источники, которые владелец передавал в ходе разработки, ресурсы, на которые ссылаются документы и наборы проекта, и локальные библиотеки файлов. Реестр нужен для обогащения каталога материалов и тематических реестров; это не разрешение на импорт и не юридическое заключение.

Актуализация 24.11.2026: официальная документация CCP подтверждает, что Static Data Export содержит игровые данные, включая карты. DLA ограничивает предоставляемую лицензию использованием приложения для поддержки игроков EVE и некоммерческого улучшения их игрового опыта; отдельное разрешение для Cockpit не установлено. EVE SDE зарегистрирован как источник только для ссылок, без скачивания/импорта. Подробности и первичные ссылки: [`setting-source-policy-eve-sde-2026-11-24.md`](setting-source-policy-eve-sde-2026-11-24.md).

Машиночитаемая версия: [`content/registries/material-sources.json`](../content/registries/material-sources.json). Действующая политика прав и подробные карточки ресурсов остаются в [`SOURCES.md`](../SOURCES.md). Специализированные своды: карты — [`M20_CARTOGRAPHIC_REGISTER_2026-11-16.md`](maps/M20_CARTOGRAPHIC_REGISTER_2026-11-16.md), 3D-ассеты — [`3d-asset-audit-2026-11-05.md`](3d-asset-audit-2026-11-05.md), SRD — [`srd-catalog.md`](srd-catalog.md) и [`srd-import-p2.md`](srd-import-p2.md), приключение LMoP — [`content-phandelver/README.md`](content-phandelver/README.md).

## Метод и границы охвата

- История ссылок восстановлена из контекста прежних разговоров, источниковых списков и handoff-документов проекта. Отдельный пользовательский URL сохраняется, если он задавал ресурс, платформу или конкретный референс.
- Проведённый поиск по текстовым файлам `SOURCES.md`, `research/`, `docs/`, `design/`, `packages/`, `scripts/`, `src/` и `content/` обнаружил 5 735 вхождений URL, 5 142 уникальные URL-строки и 217 доменов. Счёт включает адреса отдельных записей, API endpoint-ов, ссылок на документацию, проверки лицензий и технические библиотеки; это **не** 5 142 самостоятельных источника игровых материалов.
- Наибольшие повторы — отдельные статьи Forgotten Realms Wiki (3 203 URL), записи/endpoint-ы Open5e (959) и D&D 5e API (592). Для обогащения базы они сворачиваются к источнику/набору; точная ссылка страницы сохраняется у конкретной записи как `sourceRef`.
- Каталог нормализует сайт, набор данных, репозиторий, сервис или локальную коллекцию как `source`. Книга, отдельное приключение, статья, карта и API-объект остаются `sourceItem`/`sourceRef`, связанными с ним. Один сайт может содержать записи с разными редакциями и лицензиями.
- Не охвачены бинарные файлы, которые не удалось прочитать, недоступные внешние диски, все страницы каталога и полная выгрузка каждого URL. Загруженные `Neverwinter_Maps.zip` и `guide-to-neverwinter.module` остаются неинспектированными: штатная передача файлов прервалась ошибкой DNS.

## Как использовать в обогащении базы

Минимальная связь будущей карточки материала:

| Поле | Смысл |
|---|---|
| `sourceId` | Стабильный ID сайта, репозитория, набора или локальной коллекции из JSON |
| `sourceItemRef` | Точный URL страницы/записи, DOI, ID объекта или путь к файлу; не заменяется корневым сайтом |
| `materialKind` | `rule`, `monster`, `spell`, `character`, `adventure`, `location`, `map`, `asset`, `generator-output` и т. п. |
| `ruleset` / `edition` / `setting` | Отдельные значения, не выводить редакцию или сеттинг из домена автоматически |
| `provenance` | `user-history`, `project-source`, `local-file`, `web-research` с коротким объяснением, где ссылка встретилась |
| `licenseId` / `licenseScope` | Лицензия конкретного текста/файла/набора, границы медиа и атрибуция; `unknown` — допустимое явное значение |
| `decision` | Существующая политика `берём`, `факты`, `стол`, `смотрим`, `купить`, `нет` или `quarantine`; источник сам не активирует материал |
| `version` / `retrievedAt` / `checksum` | Нужны при файловом или повторяемом импорте; неизвестное не заполнять догадкой |
| `relation` | `derived-from`, `mirror-of`, `uses-as-reference`, `contains`, `same-work-as` для источников, карт и производных копий |

Сначала enrichment должен связать существующие `source`/`sourceRef` с реестром, сохранить точные URL на уровне записи и вынести право/редакцию/происхождение в отдельные поля. Новые материалы не должны попадать в активный мир из-за одного факта импорта: каталог материалов и предложения мира остаются разными слоями.

## Очередь сверки

1. Свести текущие `source` строки SRD, A5E, Black Flag, Open5e и Foundry к `sourceId`; проставить версию и лицензию на уровне записи. Это подготовка П1/П2.
2. Уточнить источники/редакции импортированных приключений и привязать карточки к метаданным Adventure Lookup или издателя, не копируя сам модуль.
3. Для M20/M21 связывать каждую точку, линию, карту и переход с точным источником и статусом геометрии; производные растры хранить отдельно от авторских реконструкций.
4. Для П6 хранить исходный файл, формат, локальный путь/хэш, источник и entitlement отдельно; импорт остаётся предложением до приёмки.
5. Для П7 сохранять источник чисел, правила, версию генератора и зерно; генератор текста не подменяет источник механики.
6. Получить доступ к Neverwinter-архивам штатным способом, затем только инвентаризировать файлы и их метаданные. Пока это блокер подтверждения, не дырка в реестре.

## Открытые вопросы

- По локальным коллекциям не подтверждены лицензии и полный состав каждого архива.
- Для пользовательской карты morePDF не установлены первичный автор, лицензия и законность копии; запись намеренно помещена в карантин.
- У большинства фанатских карт лицензия зависит от отдельной работы, поэтому реестр сайта не означает, что каждый файл этого сайта можно использовать.
- История перечисляет прежде всего URL, которые встречались в доступном контексте работы над приложением; ссылки из недоступных старых диалогов, вложенных бинарников и страниц за авторизацией могут отсутствовать.
