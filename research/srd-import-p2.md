# П2 — повторяемый импорт SRD по типам

Дата среза: 21.11.2026.

## Основа

`scripts/srd-import-registry.mjs` — единый исполняемый реестр для импортёров SRD 5.1: он связывает тип, редакцию, лицензию, основной API, дополнительные источники, импортёр и выходной JSON. Решение о допустимости источника остаётся в `SOURCES.md`, раздел 1; реестр импортёров на него ссылается.

В реестр внесены четыре уже существующих источника данных:

| Тип | Основной источник | Выходной файл |
|---|---|---|
| `monster` | dnd5eapi, блоки монстров; Open5e используется только для недостающих вводных абзацев легендарных действий | `content/srd/monsters.json` |
| `spell` | dnd5eapi, заклинания и сведения о заклинаниях подклассов | `content/srd/spells.json` |

| `rule` | dnd5eapi, оглавление разделов и вложенные заголовки/описания правил | `content/srd/rules.json` |
| `ability-score` | dnd5eapi, шесть характеристик и связи с навыками | `content/srd/ability-scores.json` |

| `trait` | dnd5eapi, 38 черт рас | `content/srd/traits.json` |

Запуск:

```sh
npm run import:srd -- --list
npm run import:srd -- monster
npm run import:srd -- --all
```

`--all` вызывает зарегистрированные импортёры по очереди. Каждый существующий скрипт сохраняет свои преобразования и `FIXES`; источник и адрес назначения теперь берутся из общего реестра.

## Повторяемость записи

Общий `writeSrdImport()` собирает одинаковые верхнеуровневые поля, сохраняет дату прежней выгрузки при совпадающем содержимом и пропускает запись файла, если JSON не изменился. При обновлении данных дата меняется; новый файл подготавливается рядом с целевым и атомарно переименовывается после полного успешного импорта. Поэтому сетевой сбой до сборки результата не заменяет текущий набор частичным.

## Завершение

20.11 добавлен `scripts/import-srd-languages.mjs`: он сверяет полный список индексов API с текущим перечнем из 16 языков, загружает детальные записи параллельно, проверяет обязательные поля и сохраняет только нормализованные данные каталога через общий атомарный writer. Полученный снимок лежит в `content/srd/languages.json`.

21.11 добавлен `scripts/import-srd-rules.mjs`: он сверяет список из 137 элементов дерева правил, загружает подробные записи, проверяет имена, описания, связи родитель/дочерние элементы, циклы и шесть корневых разделов. Снимок получил отдельный пакетный манифест с лицензией CC BY 4.0 и регистрируется в каталоге как 137 ссылок на локальный источник. Двойной запуск завершился одинаковым результатом: второй раз `content/srd/rules.json` остался `UNCHANGED`. Каталог содержит 2 115 записей, из них 309 правил.

Также добавлены `scripts/import-srd-ability-scores.mjs` и `scripts/import-srd-skills.mjs`. Они требуют точный набор из 6 характеристик и 18 навыков, сверяют имена, описания и связи навыка с характеристикой, нормализуют поля и пишут через общий атомарный writer. Оба снимка назначены пакету `dnd5e-2014`; повторный прогон каждого завершился `UNCHANGED`. Существующие ID каталога сохранены, а `sourceRef` теперь указывает на импортированную строку.

В реестре 20 импортёров для 20 типов каталога. Расы, классы и связанные сущности импортируют самостоятельные снимки, сохраняя имеющиеся переводы и редакторские поля в `content/compendium/`; каталог связывает совпадающие базовые записи с API по явным английским именам/ID. 407 API-умений классов, 38 API-черт рас и 25 групп выбираемых вариантов включены отдельными API-ID, а не подменяют русские записи. Для `class-option` API не имеет отдельного ресурса: импортёр проверяет список 407 feature-ID и контрольную сумму 25 записей с `feature_specific`.

Полный проход выполнен по каждому импортёру отдельно, без `--all`: четыре исходных импорта вернули `UNCHANGED`; остальные снимки повторно запущены и тоже вернули `UNCHANGED`. Каталог — 14/14 тестов, реестр — 4/4, TypeScript и пакетная проверка прошли. П2 закрыта для всех каталоговых типов. П1 относится к установленным данным и не доказывает, что импортирован весь текст/каждая запись книги SRD 5.1.

Сетевые снимки получены из разрешённых ресурсов dnd5eapi. `--all` не запускался, но каждый из 20 зарегистрированных импортёров проверен прямым запуском; четыре крупных исходных снимка остались `UNCHANGED`. Контракт общего writer отдельно проверяет идентичную запись, атомарную замену и дату снимка.
