# MapTool как временная площадка вместо Foundry

Проверено по документации RPTools в сентябре 2026. На тот момент последним подтверждённым стабильным релизом был MapTool 1.18.6 от 30 октября 2025; это исторический срез проверки, а не заявление о текущем релизе. Протокол моста отдельно сверялся с исходниками 1.18.7 — это версия проверенных исходников, не утверждение о стабильном выпуске. На ручной приёмке нужно записать фактически установленную версию.

## Что MapTool умеет из нужного нам

- **Add-on library** — это zip с расширением `.mtlib`: `library.json` (имя, авторы, namespace), `events.json` (обработчики `onFirstInit`, `onInit` и события вроде `onTokenMove`), `mts_properties.json`, макросы MTScript в `library/mtscript/`, и — главное для нас — `library/public/` с JavaScript, HTML и CSS, доступными по `lib://namespace/путь`.
- **HTML5-окна**: `frame5` и `dialog5` открывают WebView и грузят содержимое по `lib://` или по URL. В такое окно помещается собранное React-приложение — это ровно наш рабочий стол.
- **REST-функции** MTScript: `REST.get`, `REST.post`, `REST.put`, `REST.patch`, `REST.delete`, возвращают тело и код ответа. Работают **только из доверенного макроса** (Trusted Macro), то есть у мастера.
- **Хранилище**: свойства библиотеки (`setLibProperty` / `getLibProperty`) держат JSON без превращения в строку — годится как кэш состояния на стороне MapTool.
- **Режим игроков** встроен: у игроков своё окно с картой и туманом. Это прямо соответствует F8.

## Что MapTool не даёт

- **Нет модели данных 5e.** MapTool системно-нейтрален: у токена есть произвольные свойства, но нет актёров, предметов и заклинаний как сущностей. Foundry с системой dnd5e даёт это из коробки. Для нас это не потеря: карточки сущностей и правила всё равно живут в DM Cockpit, а MapTool получает только то, что нужно нарисовать на столе.
- **JS-API добрее к макросам, чем к скриптам.** JavaScript в add-on выполняется через `js.evalURI(context, uri)`, но значительная часть работы всё равно идёт через MTScript, и API беднее, чем у Foundry с его документами и хуками. Мост придётся писать на MTScript, а не только на JS.
- **WebView — не Chrome.** Встроенный движок Java-приложения; пиксельные шрифты, `image-rendering: pixelated`, `box-shadow` для рамок и скролл длинных панелей нужно проверить руками на первом же спайке.

## Вывод

**Да, MapTool — разумная временная площадка,** при условии, что он остаётся столом, а не источником правды. Разделение:

| Что | Где живёт |
|---|---|
| Мир, факты, нити, журнал, симуляция, решения мастера | DM Cockpit |
| Карта боя, токены на столе, движение, туман для игроков | MapTool |
| Перевод одного в другое | адаптер `VttAdapter` из раздела «Передача в Claude Code» |

## Отвергнутый ранний набросок

Первоначальная схема предлагала `onTokenMove` для отправки движения и отдельный `REST.get` для команд в обратную сторону, а урон/состояния — отдельными вызовами доверенного макроса. Этот вариант не стал контрактом: `onTokenMove` вызывается до перемещения и может его запретить. Реализован единый опрос состояния карты и обмен одним запросом, описанный ниже.

## Мост сделан — 29.10.2026 (Q17, шаг 12)

Окно аддона (`html.frame5`, `lib://net.dmcockpit.bridge/bridge.html`) раз в секунду вызывает доверенный макрос `sync@lib:net.dmcockpit.bridge`. Макрос отправляет один `REST.post` на `/vtt/maptool/sync` со снимком `{ map, tokens: [{ id, name, x, y }]}` и получает представление стола `{ rev, tokens: [{ tokenId, hp, states }], managed }`. Страница стола опрашивает `/vtt/desk/poll`, превращает новые клетки известных токенов в `TOKEN_MOVED` и отправляет актуальные хиты/состояния на `/vtt/desk/view`; ответ на следующий вызов макроса отображает их на токенах. Ретранслятор хранит только последнее состояние в памяти dev-сервера. Маршрутов моста нет в статической сборке. Протокол и вызовы сверены по исходникам MapTool 1.18.7 (`AddOnLibrary`, `RESTfulFunctions`, `RequestHandler`, `MTXMLHttpRequest`).

| Направление | Правда | Как |
|---|---|---|
| Клетка токена | MapTool | снимок → `movesFromSnapshot` → событие `TOKEN_MOVED` (решение владельца 29.10.2026), `source: 'maptool'`; в журнале «Korrin Battlehammer: клетка (2, 2) → (4, 3) · MapTool» |
| Хиты, состояния | лог стола | `vttView` → полоса Health, подпись «42/49 +5» и соответствующие именованные состояния MapTool (`Prone`, `Blinded`…; ноль хитов — `Dead` у монстра, `Incapacitated` у героя) |

- Токен связан с актёром по имени: id актёра, имя целиком или одно слово имени, если оно только у одного актёра («Aldric» — Brother Aldric; «Bandit» — никто, их четыре). Сопоставляет стол, макрос получает готовый список по id токенов. Токены без актёра чип «MapTool» в шапке поля боя перечисляет в подсказке.
- Отменённый на столе ход не возвращается следующим опросом: ход — только перемена в MapTool между снимками. Первый снимок выравнивает стол по MapTool, кроме актёров, уже стоящих на своей клетке или клетке сида.
- При переходе на карту с другим именем первый снимок становится её базой и не порождает `TOKEN_MOVED` для позиций относительно предыдущей карты. Relay включает имя карты в `seq`; распознавание перехода зависит от MapTool `getCurrentMapName()`, поэтому одинаково названные карты неразличимы этим протоколом.
- Клетка за краем сетки стола (12 × 8) не рисуется — в MapTool зона больше.
- Ретранслятор — middleware сервера разработки (`vite.config.ts`, `src/vtt/relay.ts`), в памяти: перезапуск ничего не теряет. В статической сборке его нет — стол о мосте молчит.

**Как включить для проверки.**

1. `scripts/maptool/build-bridge.sh` → `maptool/dm-cockpit-bridge.mtlib`.
2. Запустить DM Cockpit через `npm run dev` на той же машине, где запущен MapTool. В настройках MapTool включить **Allow External Macro Access** — иначе `REST.post` запрещён.
3. File → Add On Libraries → Add → `dm-cockpit-bridge.mtlib`. Откроется окно «DM Cockpit»: «на связи» — стол отвечает; «нет связи» — не запущен `npm run dev` (порт 5180).
4. Имена токенов — как актёры стола (Korrin, Bo, Lyra, Aldric, Bandit Captain, Bandit 1…). Сетка карты — квадратная, клетка 5 футов.

**Оставшийся gate — ручная приёмка мастером на Windows.** Проверить на ноутбуке мастера Acer Nitro V 15 ANV15-52 с установленным MapTool: загрузить собранный add-on и подтвердить в живом обмене (1) перемещение сопоставленного токена создаёт в DM Cockpit правильный `TOKEN_MOVED`, (2) изменение хитов и состояний в DM Cockpit обновляет Health, подпись и поддерживаемые состояния токена. Записать версию MapTool и результат обеих проверок; до этого сквозная приёмка не считается закрытой.

*Не реализовано в текущем мосте:* создание/перестановка токенов из стола в MapTool (мастер перемещает их в MapTool); концентрация и временные эффекты на токене; веса и размеры токенов; синхронизация тумана и видимости фактов игрокам.
