# БА20 · физический ввод дайса с откликом

Дата: 14.11.2026  
Статус: принята только интерфейсная вертикаль ручного физического ввода; БА20 остаётся открытой.

## Что проверялось

В качестве примера взяты Pixels: физический бросок передаёт верхнюю грань по Bluetooth, а кость и приложение могут давать световой/звуковой отклик. Руководство производителя отдельно подчёркивает асинхронное соединение, потерю связи, повторные броски и необходимость оставить виртуальный бросок доступным. В текущем проекте нет подключённого BLE-адаптера или самого устройства, поэтому экран не притворяется сопряжённым с дайсом.

## Реализованный поток

- В панели «Действия» добавлен раскрываемый блок «Физический дайс» с d4, d6, d8, d10, d12, d20 и d100.
- Мастер вводит наблюдённую верхнюю грань, модификатор и подпись, затем подтверждает событие.
- Результат записывается как `DICE_ROLLED` с `origin: physical-manual`, участвует в обычной карточке/истории и сохраняет стандартную маркировку натуральных 20 и 1.
- После подтверждения появляется крупный итог и live-region для объявления результата; произнесение числа через браузер включается отдельно и выключено по умолчанию.
- Скрытость броска наследуется от действующего переключателя мастера. В режиме просмотра реплея физический ввод скрыт.
- Раскрытый ввод закрывается клавишей Esc. Правая панель теперь прокручивается по вертикали; горизонтальная прокрутка скрыта.

## Браузерная приёмка

Стенд: изолированный `http://localhost:5180/` с отдельным origin для пробных событий. Состояние кампании на `127.0.0.1` не затрагивалось. Три демонстрационных броска остались в локальном журнале origin `localhost`; очистку не подтверждал, поскольку штатная кнопка новой сессии предупреждает о необратимом стирании журнала.

| Проход | Результат |
|---|---|
| 1280×720 | Форма, подпись, переключатель озвучивания и подтверждение видны; исправлено первоначальное обрезание нижней части панели. |
| 1024×576 CSS px (эквивалент 1280×720 при 125%) | Форма и кнопка подтверждения остаются видимыми, панель использует вертикальную прокрутку без горизонтальной. |
| d20: 20 + 5 | В журнале появился `1d20+5 = 25`; карточка явно помечена «Физический», показан «Крит». |
| d20: 1 + 5 | В журнале появился `1d20+5 = 6`; карточка показывает «Провал». |
| Клавиатура | Esc, нажатый из поля подписи, свернул блок ввода. |
| Секретность | Включённый `hiddenRolls` создал скрытое событие; в режиме игроков его подпись/результат и мастерская форма отсутствовали в дереве доступности. |
| Ошибка ввода | Для d20 значение 21 заблокировано встроенной валидацией поля (`Значение должно быть меньше или равно 20`); новое событие не создано. |

Снимки экранов сделаны во время браузерного прохода; отдельные PNG-файлы в проект не добавлялись. Автоматические тесты не запускались. `git diff --check` прошёл. Типовая проверка `npx tsc --noEmit -p tsconfig.app.json` сообщила только две существующие ошибки в тестовых фикстурах `PreparedSimulation` (`CaravanPlanner.test.tsx` и `caravanPlanning.test.tsx`); ошибок в новых/изменённых исходниках она не показала.

## Остаток БА20

Это рабочий интерфейс для ручного ввода результата обычного физического дайса, а не автоматическая интеграция Pixels. Не реализованы BLE-сопряжение и повторное подключение, чтение результата с устройства, отправка LED-анимации/звука на сам дайс, обнаружение ошибочного/повторного броска и обработка ошибок устройства. Для этого нужен отдельный подключённый адаптер, предпочтительно поверх официального `@systemic-games/pixels-web-connect`, и приёмка с реальным устройством в поддерживаемом Chromium-браузере.

Источники:

- [Pixels: устройство и обратная связь](https://gamewithpixels.com/pages/circuit-board)
- [Pixels: статусные LED-паттерны](https://gamewithpixels.com/pages/led-indicators)
- [Pixels Developer's Guide](https://github.com/GameWithPixels/.github/blob/main/doc/DevelopersGuide.md)
- [Официальный веб-пакет Pixels](https://www.npmjs.com/package/@systemic-games/pixels-web-connect)
