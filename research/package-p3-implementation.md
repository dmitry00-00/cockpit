# П3 — реализация формата пакета сеттинга и пакет Forgotten Realms

Дата: 20.11.2026. Реализация проверялась в изолированном снимке текущей рабочей копии; общая копия проекта не очищалась и не сбрасывалась.

## Что добавлено

- Манифест setting-пакета связывает календарь и профиль линз с отдельными слоями, объявляет лестницу масштабов, паспорта карт и очищенные карты. Все ссылки должны указывать на зарегистрированный слой правильного типа.
- `check-packages.mjs` валидирует профили календаря, линз и лестницы; проверяет карты, ссылки на корни, совместимые картриджи правил и подписи пользовательских видов. Генератор сохраняет в компактном индексе только runtime-поля, включая `kinds`.
- Формат календаря 1 принимает `months`, `counter` и `gregorian`. Для всех трёх есть валидация и adapter; проверены вставные/повторяющиеся дни, абсолютный счётчик дней, високосность Григорианского календаря и эпоха. Для `counter` `yearAt()` возвращает `null`. Безгодовой календарь показывает только дни на ленте, не подгружает хронику Forgotten Realms и не предлагает годовую линзу; годовые редакционные профили берут `default` из манифеста.
- Панель времени не показывает Harptos, астролябию, лунную фазу и погоду для календарей других видов; для них выводит дату и время из adapter. `ChronologyView` доступен только пакету Forgotten Realms.
- Линза Forgotten Realms задаёт границы 3e/4e/5e, порядок чтения редакционных полей и космологию.
- Профиль лестницы задаёт значения всех девяти стабильных рангов: русскую подпись, рекомендованный темп, представление, карту и корневые места. Сид кампании создаёт корневые места из этого профиля, сохраняя прежние ID и ссылки.
- Манифест `fr` теперь включает 58 слоёв. Проверка нашла 69 файлов в `content/`; каждый принадлежит ровно одному слою. Включены два паспорта карт, очищенный паспорт Toril и три новых профиля: Harptos, линза редакций и лестница масштабов.
- **20.11:** сезонное предложение в `src/campaign/simulation.ts` теперь использует `calendarAdapterForState(state)`: переход, подпись сезона и имя мира берутся из выбранного setting package/runtime state. Если календарь не описывает сезоны, сезонное предложение не создаётся; если в мире не ровно одна планета, вместо произвольного выбора показывается общее «Сезон».
- На другом пакете дополнительно не создаются текущие FR-сценарии: наценка Neverwinter за караван, лунное событие в Neverwinter Wood, цены еды по Harptos и святые дни богов FR. Для пакета по умолчанию поведение сохраняется. Эти данные не переехали в манифест и ещё не переиспользуются другими сеттингами; постоянный контракт предметных правил симуляции остаётся будущей частью П3.
- **20.11:** `src/entities/index.ts` выводит выбранный setting package из контекста или `State`; для setting-зависимых кэшей ключ включает пакет. FR-загрузчики `cosmos`, `places`, `world`, `kingdoms` не вызываются для других пакетов, пока их манифесты не объявят поддерживаемые слои сущностей. `useEntity` и карточки в Desk передают выбор кампании, а смена пакета на открытой карточке переключает разрешение на отдельный кэш. Это защищает от показа FR-сущностей в другом сеттинге, но не загружает его собственные записи.
- **20.11:** `scripts/check-packages.mjs` включает в runtime index объявленные манифестом layer descriptors `{id,path,kinds}`; `packageLayersForKind(packageId, kind)` возвращает только такие слои. В изолированно сгенерированном индексе FR `deity` находит `content/cosmos/deities.json`, `kingdom` — `content/world/kingdoms.json`, `place` — только слои, помеченные `place`. Девять таких слоёв неоднородны: среди них GIS-оверлеи и `.jsonl`, поэтому resolver — только каталог заявленных слоёв, а не схема entity records. Универсального преобразования разнородных JSON в `EntityView` пока нет.
- **20.11:** выбор паспорта/плана карты кампанией проверяет ID владельца из манифеста (`settingPackageForMap`). `mapById` и `planOf` по умолчанию сохраняют пакет `fr`; активный пакет явно передаётся из `levelMap`, `LevelZone` и `suggestNpcName`. Если географическая ссылка кампании указывает на чужой паспорт, карта не строится и генератор локальных имён не использует чужой gazetteer-паспорт. Это изолирует выбор карты, но не закрывает пакетную параметризацию всех картографических загрузчиков. Прикладной TypeScript и `git diff --check` прошли; автотесты не запускались.

## Проверки

- `node scripts/check-packages.mjs` — успешно: 5 манифестов, 69 файлов `content/`, назначение каждого ровно одному слою.
- Целевые Vitest: 81/81 прошли в 8 файлах (календарь, эпохи, seed, лестница, сущности, лента, часы). В изолированном снимке использован временный тестовый конфиг без тяжёлой глобальной предзагрузки приложения; конфиг не входит в поставку.
- `npx tsc --noEmit -p tsconfig.app.json` — новых ошибок в изменённых П3-файлах нет; команда остаётся красной на трёх известных ошибках престижных событий A5E в `engine/reduce.ts` и `pages/desk/helpers.ts`.

## Остаток приёмки на 20.11.2026

П3 не закрывается одной проверкой манифеста. В продукте ещё есть FR-специфичные загрузчики карточек и данных (`PACK_OF`/`LOADERS`, вызовы Toril-справочников) и недостающий пакетный контракт для правил праздников, погоды и других эффектов. Текущие FR-сценарии симуляции явно пропускаются для иных пакетов; сезонные метки читаются из их календаря, если профиль их объявляет. Это не доказывает подключение произвольного второго сеттинга без изменений `src/`. Planetos остаётся отложенным по решению владельца; его пилот нельзя подменять синтетическим тестом календаря.

До закрытия П3 остаются: построить package-specific entity projection из объявленных слоёв; перевести Harptos-only year stepping, pulse, scene/tension, economy, caravan/process и остальные FR/Toril-связи на пакетный контракт; параметризовать эффекты; затем принять второй пакет. Planetos/M11 остаётся отложенным владельцем, поэтому его приёмка пропущена. Визуальная CUA-приёмка приложения в этом заходе не проводилась.

## Продолжение 21.11.2026

- «Пульс» получил выбранный календарный адаптер: переходы сезонов читаются из календаря пакета, а луна — из его профиля, если календарь её объявляет. Праздники Харптоса, Selûne, святые дни и связи справочника божеств вычисляются только для Forgotten Realms.
- `sceneOf` выводит дату, сезон и (если объявлена) луну через календарь кампании. Форматирование дат сроков процессов тоже использует его. Праздники Харптоса, Selûne, погода и хронология FR не попадают в сцену другого пакета; `Scene.year` теперь nullable для календаря без года.
- `useScene` загружает Toril-справочник и хронологию только для кампании FR с календарным годом.
- Годовой шаг времени использует `CalendarAdapter.addYears()`: месячные календари переносят вставной день на ближайший доступный день до него, григорианский календарь сохраняет месяц/время и ограничивает дату концом месяца, а календарь без года 0 перескакивает его. Календари без лет скрывают годовой темп и не принимают такой шаг. Проекторы напряжений и FR-инструменты войн, городов и космических процессов теперь привязаны к пакету FR.
- Разрешение карточек берёт год и эпоху из календаря/линзы выбранного setting package. Карточка божества персонажа и уровни FR-космологии больше не вычисляют год по Харптосу другой кампании.
- Добавлен строгий JSON-контракт `cockpit.entity-layer/1`: общий resolver читает только объявленные слои со стандартными `EntityView`, проверяет ссылки, поля, источник и дубликаты; загрузка адресная по виду. Существующие неоднородные данные FR продолжают использовать специализированные loaders. Файл контракта и ограничения описаны в `research/setting-package.md`.
- Остаточные места Desk, завязанные на Харптос, переведены на выбранный пакет: эпоха новых персонажей и карточек берётся из его линзы; экран времени показывает дату адаптера и только объявленные им фазы/луну; FR-календарь, Selûne и Toril wiki lookup остаются только у FR. Хронологическая лента и сохранённая линза не запускают FR-загрузчики в другом пакете. Праздник и святые дни в пустой панели входящих показываются только для FR; для остальных — нейтральное «Мир спокоен». Подготовка хроники сущности прекращается вне FR, generic entity card остаётся без FR subject envelope, а кэш карточки учитывает setting package. На карте не выводятся FR-погода и A5E-региональные погодные слои в другом пакете.
- `git diff --check` прошёл. Автотесты, прикладной TypeScript и визуальная CUA-приёмка в этой итерации не запускались.

До закрытия П3 остаются: подключить к entity-layer/1 реальные слои второго setting package; ввести package-aware модель и экран хроники; перевести оставшиеся FR/Toril-зависимые механики экономики, караванов/процессов и загрузчиков данных на пакетный контракт; параметризовать эффекты; затем принять второй пакет. Planetos/M11 остаётся отложенным владельцем, поэтому его приёмка пропущена. Визуальная CUA-приёмка приложения не проводилась.

TypeScript и `git diff --check` прошли 20.11.2026 после изменения entity-загрузчиков. Python AST parse импортёра staging также прошёл. Автотесты и browser acceptance в том заходе не выполнялись.
