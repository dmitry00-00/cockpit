# MapTool как временная площадка вместо Foundry

Проверено по документации RPTools в сентябре 2026. Последний стабильный релиз, который удалось подтвердить, — MapTool 1.18.6 от 30 октября 2025; ночные сборки продолжают выходить (последние — сентябрь 2026), то есть проект живой.

## Что MapTool умеет из нужного нам

- **Add-on library** — это zip с расширением `.mtlib`: `library.json` (имя, авторы, namespace), `events.json` (обработчики `onFirstInit`, `onInit` и события вроде `onTokenMove`), `mts_properties.json`, макросы MTScript в `library/mtscript/`, и — главное для нас — `library/public/` с JavaScript, HTML и CSS, доступными по `lib://namespace/путь`.
- **HTML5-окна**: `frame5` и `dialog5` открывают WebView и грузят содержимое по `lib://` или по URL. В такое окно помещается собранное React-приложение — это ровно наш рабочий стол.
- **REST-функции** MTScript: `REST.get`, `REST.post`, `REST.put`, `REST.patch`, `REST.delete`, возвращают тело и код ответа. Работают **только из доверенного макроса** (Trusted Macro), то есть у мастера.
- **Хранилище**: свойства библиотеки (`setLibProperty` / `getLibProperty`) держат JSON без превращения в строку — годится как кэш состояния на стороне MapTool.
- **Режим игроков** встроен: у игроков своё окно с картой и туманом. Это прямо соответствует F8.

## Что MapTool не даёт

- **Нет модели данных 5e.** MapTool системно-нейтрален: у токена есть произвольные свойства, но нет актёров, предметов и заклинаний как сущностей. Foundry с системой dnd5e даёт это из коробки. Для нас это не потеря: карточки сущностей и правила всё равно живут в DM Cockpit, а MapTool получает только то, что нужно нарисовать на столе.
- **JS-API добрее к макросам, чем к скриптам.** JavaScript в add-on выполняется через `js.evalURI(context, uri)`, но значительная часть работы всё равно идёт через MTScript, и API беднее, чем у Foundry с его документами и хуками. Мост придётся писать на MTScript, а не только на JS.
- **WebView — не Chrome.** Встроенный движок Java-приложения; пиксельные шрифты, `image-rendering: pixelated`, `box-shadow` для рамок и скролл длинных панелей нужно проверить руками на первом же спайке.

## Вывод

**Да, MapTool — разумная временная площадка,** при условии, что он остаётся столом, а не источником правды. Разделение:

| Что | Где живёт |
|---|---|
| Мир, факты, нити, журнал, симуляция, решения мастера | DM Cockpit |
| Карта боя, токены на столе, движение, туман для игроков | MapTool |
| Перевод одного в другое | адаптер `VttAdapter` из раздела «Передача в Claude Code» |

Практическая схема первого спайка:

1. DM Cockpit поднимает локальный HTTP-сервер (он и так нужен для одной сессии без облака).
2. В MapTool ставится add-on: `onTokenMove` шлёт `REST.post` с координатами токена, доверенный макрос по кнопке шлёт урон и состояния.
3. В обратную сторону DM Cockpit отдаёт команды, которые макрос забирает опросом `REST.get`, — вебсокета в MTScript нет, поэтому пока опрос раз в секунду.
4. Рабочий стол мастера при желании открывается прямо в `frame5` — но на первом спайке лучше держать его в браузере: одним неизвестным меньше.

Риск, который надо принять сознательно: мост на MTScript придётся выбросить при переезде на Foundry. Он того стоит, если адаптер отделён интерфейсом и не протёк в модель, — тогда выбрасывается один файл, а не половина продукта.
