# DM Cockpit — пакет передачи

Электронная ширма мастера D&D 5e: операционная система живого мира.

Здесь всё, что нужно, чтобы начать разработку, не переоткрывая решений. Оригинальный бриф и дизайн-система больше не нужны — пакет самодостаточен.

## Читать в таком порядке

1. **`CLAUDE.md`** — правила, которые нельзя нарушать. Кладётся в корень репозитория: агент читает его сам.
2. **`HANDOFF.md`** — полная спецификация: архитектура, девять экранов, доменные события, компоненты, стек, план первых шагов.
3. **`BRAND.md`** — бренд-бук: тон, цвет, типографика, форма, иконки, движение.
4. **`vtt-maptool.md`** — разбор MapTool как временного стола вместо Foundry.

Python-инструменты (маски планет, импорт компендиума): `zsh setup-python.command` (или двойной клик) — создаёт `.venv` с Pillow и openpyxl рядом; повторный запуск безопасен.

## Установка и запуск

Репозиторий — https://github.com/dmitry00-00/cockpit. Установочные скрипты лежат в корне и ничего системного не трогают: свой Node.js (если в системе нет ≥ 20), `node_modules`, сборка и отпечаток `package-lock` живут внутри пакета (`.tools/` — не в git). Повторный запуск безопасен; запущенный не из пакета скрипт сам берёт его из репозитория в `~/cockpit` (или `$COCKPIT_DIR`).

| | Mac | Windows |
|---|---|---|
| Установить и проверить | `setup.command` (двойной клик или `zsh setup.command`) | `setup.cmd` (двойной клик; зовёт `setup.ps1` через `powershell.exe -ExecutionPolicy Bypass`) |
| Одной командой без пакета | `curl -fsSL https://raw.githubusercontent.com/dmitry00-00/cockpit/main/setup.command \| zsh` | в PowerShell: `irm https://raw.githubusercontent.com/dmitry00-00/cockpit/main/setup.ps1 -OutFile $env:TEMP\setup.ps1; powershell -ExecutionPolicy Bypass -File $env:TEMP\setup.ps1` |
| Играть | `start.command` — http://localhost:5180 в браузере, стол живёт, пока открыто окно | `start.cmd` — то же |
| Планшет / второй экран по сети | `zsh start.command --lan` | `start.cmd -Lan` |
| Свежий код из репозитория | `zsh setup.command --update` | `setup.cmd -Update` |
| Полный прогон тестов | `zsh setup.command --test` | `setup.cmd -Test` |
| Сервер разработки вместо `dist/` | `zsh start.command --dev` | `start.cmd -Dev` |

Что делает установка: находит Node.js ≥ 20 (PATH, Homebrew, nvm, volta; на Windows — Program Files, nvm-windows, volta, fnm) или скачивает закреплённый v22.23.0 с nodejs.org в `.tools/node` со сверкой SHA-256; `npm ci` ровно по `package-lock.json` (повторно — только если lock сменился); `npm run build` (тема, иконки, `tsc`, `vite build`); поднимает собранный стол на порту 5181 и проверяет, что он отдаёт страницу. Запуск собирает заново только если `dist/` старее исходников; второй двойной клик при работающем столе просто открывает браузер. Скрипты держит `scripts/setup.test.mjs`: одна версия Node.js и суммы архивов в обеих версиях, права на `.command`, BOM в `.ps1` (Windows PowerShell 5.1 без него читает кириллицу как ANSI), CRLF в `.cmd`.

Mac: пакет, скачанный архивом через Safari, несёт карантин — первый запуск `.command` через правый клик → «Открыть» (или `zsh setup.command`). Windows: `--lan` попросит разрешить `node.exe` в брандмауэре — один раз.

## Разработка

Код живёт в этом же каталоге (`CLAUDE.md` — в корне репозитория, как и задумано). Стек — HANDOFF §11: Vite 6 · React 19 · TypeScript 5.9 · Tailwind 4 · Radix (`radix-ui`) · Vitest 3.

```bash
npm install
npm run dev          # http://localhost:5180 — пересобирает тему и поднимает Vite
npm test             # тема + контраст токенов + паритет с tokens.css + сторож радиуса + страницы
npm run build        # тема → tsc → vite build
npm run build:theme  # только тема: design/tokens.json → src/styles/theme.generated.css + tokens.generated.ts
npm run build:icons  # только иконки: design/icons-generator.js → src/icons/icons.generated.ts + public/icons/atlas.{png,json}
node scripts/import-srd-monsters.mjs   # библиотека монстров SRD с dnd5eapi.co → content/srd/monsters.json (нужна сеть; набор — списком в скрипте)
```

Правила кода, которых нет в документах дизайна:

- **Тема — только из `design/tokens.json`.** `scripts/build-theme.mjs` пишет `src/styles/theme.generated.css` (переменные `:root` с именами токенов, тема Tailwind с `--*: initial`, стили типографики) и `src/styles/tokens.generated.ts` (те же токены данными). `*.generated.*` не правятся руками и не коммитятся. `design/tokens.css` в продукт не импортируется; тест `tokens-css-parity` держит его равным сгенерированному.
- **Стили типографики в разметке — `type-<имя>`:** `type-h-28`, `type-body`, `type-num-15`, `type-key`. Имена стилей `h-28`, `h-20`, `h-17`, `h-15` совпадают с высотами Tailwind (`h-15` = 60px), поэтому без префикса применялись бы обе утилиты.
- **Цвета — `bg-pn`, `text-t2`, `shadow-bevel`** и так далее, по именам токенов; произвольных значений (`bg-[#…]`) не бывает — новый цвет сначала становится токеном с посчитанным контрастом. Контрасты из `usage` пересчитываются тестом `contrast.test.ts`: 18.09 он поймал две неверные цифры в токенах (`src-canon`, `src-players`).
- **Сетка 4px:** `--spacing: 4px`, то есть `p-1` = 4px, `p-2` = 8px, `gap-4` = 16px; размеры полос и панелей — `h-bar-clock`, `w-rail-party` из `--size`-токенов.
- **Радиус:** `*, ::before, ::after { border-radius: 0 }` в базовом слое, а `radius.test.ts` ищет в исходниках любой `border-radius` кроме нуля и любой `rounded-*`.
- **Иконки — только из генератора.** `scripts/build-icons.mjs` читает `design/icons-generator.js` (файл остаётся CommonJS при `"type": "module"` — скрипт компилирует его в CJS-обёртке, побочный `icons.out.js` не пишется) и отдаёт два выхода из одного описания: `src/icons/icons.generated.ts` для DOM и `public/icons/atlas.png` + `atlas.json` (spritesheet PixiJS) для канваса. Компонент — `src/icons/Icon.tsx`: `name`, `size` 16/24/32/48, `color` (перекраска всех четырёх тонов по `pal()` генератора), обязательный `title`; один `<path>` на тон. Сборка сверена с `reference/components/icons-*.png` попиксельно: 105 из 105.
- **Event log — `src/engine/`** (шаг 3): `events.ts` — двадцать два типа (тринадцать из HANDOFF §7 плюс восемь по решению владельца 19.09.2026: бой, концентрация, актёры, предложение; плюс отдых — 21.09.2026) с payload и таблицей обратимости; `reduce.ts` — чистый редьюсер `apply(state, event) → { state, effect }` на Immer, проверка команды до записи; `log.ts` — `EventLog` (dispatch, undo/redo компенсирующими событиями с `undoes`/`redoes`, реплей, `check`); `journal.ts` — проекция в записи журнала по-русски; `dice.ts` — формулы `NdM±K` с внешним rng; `persist.ts` — `localStorage` и память за одним интерфейсом; `store.ts` — Zustand-обёртка с `damage/heal/tempHp/rollDice/advanceTime/nextTurn`, тостом до следующего действия, и с 19.09 — `startEncounter/endEncounter/setInitiative/startConcentration/endConcentration/spawn/remove/propose`. Компоненты стор не читают — получают state пропсами (CLAUDE.md).
- **Правила SRD — `src/rules/srd/`**: 15 состояний с дословным текстом SRD 5.1 и русскими подписями, истощение уровнями, DC, `concentrationSaveDc`, укрытие, свет, действия в бою; монстры — форма и доступ над `content/srd/monsters.json`; атрибуция CC-BY-4.0 в `LICENSE.md`. Тексты не по памяти — сняты с открытого API SRD.
- **Компендиум — `content/compendium/`** из двух наработанных таблиц в корне пакета (`Копия расы.xlsx`, `Копия файла _Копия Классы.xlsx_.xlsx`): `.venv/bin/python scripts/import-compendium.py` → `races.json`, `feats.json`, `classes.json`, `report.md`. Модель — `src/rules/compendium/schema.ts`: раса → подрасы с числовыми ASI, черты с фасетом (`kind`), черты (feats) с требованиями и колонками эффектов, класс → 20 уровней с умениями и ресурсами → подклассы с уровнем получения. Серые отметки фасетных колонок таблицы (`facetMarks`) стоят лишь у части рас и показываются отдельно от черт. Каждая запись несёт `source`: `srd` (9 рас, 4 подрасы, 12 классов, по одному подклассу, черта Grappler), `book`, `hb`. Данные для них считают чистые функции `src/rules/compendium/views.ts` (`raceFacetRows`, `classLevelGrid`, `featRows`; порядок колонок — по частоте во всём компендиуме, чтобы заполненные были видны без прокрутки и не скакали от фильтра). Фильтр источников `SRD / книга / HB`, поиск, клик по клетке — текст в панели подробностей с адресом клетки таблицы. Глубокие ссылки: `#/compendium/classes/volsebnik`, `#/compendium/feats`.
