## 1. Официальный источник agent-gw — его нет

Проверено сейчас:

- На PyPI пакета `agent-gw` **нет** (запрос к `pypi.org/pypi/agent-gw/json` возвращает 404). Публичной установки через `pip` не существует.

- Публичной документации по внешнему использованию SDK я не нашёл. Более того, в официальном репозитории Kimi Code есть открытый issue (от 26.10.2026), который запрашивает ровно это: авторизован ли ключ Kimi Code для вызова `agent-gw` `client.tools.generate_image`, какие правила квот и биллинга — и фиксирует, что «SDK availability alone does not clarify external authorization or billing». Официального ответа в issue я при выгрузке не увидел — статус вопроса: открыт.

## 2. Поддерживаемый доступ к генерации для обычного аккаунта

**Изображения.** Публичного Images API у Moonshot нет: Kimi API документирует анализ изображений (image understanding через base64/data URI), но не генерацию. Генерация изображений — функция веб-продукта (плагин в Kimi Work), оплачивается подпиской, программно не открыта.

**3D.** Движок моего плагина — Tripo, и у Tripo есть **свой публичный API**: REST `POST https://api.tripo3d.ai/v2/openapi/task` и официальный Python SDK (`TripoClient` с `text_to_model` / `image_to_model` / `multiview_to_model` / `wait_for_task` / `download_task_models`). Это тот же стек (GLB/FBX/OBJ, face_limit, texture_quality, multiview), что и у меня внутри — то есть Codex получит эквивалентные результаты без моего участия. Есть и альтернативный хостинг той же модели: Tripo H3.1 image-to-3d доступен на fal.ai с очередью, вебхуками и своим файловым хранилищем.

**Агентный доступ к Kimi извне (без генерации).** Официально существует **Kimi Agent SDK** — мультиязычные библиотеки, которые программно управляют рантаймом Kimi Code CLI: сессии, промпты, стриминг, кастомные инструменты. Python: `pip install kimi-agent-sdk`. Это поддерживаемый способ «отправлять задания агенту и получать результаты» — но агентом будет локальный Kimi Code, не веб-чат, и инструментов генерации в нём по-прежнему нет.

## 3. Минимальный внешний пример (3D, без ключей)

Поток «референс → генерация → файл» через официальный Tripo API. Шаги и названия операций подтверждены документацией платформы (`platform.tripo3d.ai/docs/generation`); точные имена полей сверьте по ней перед запуском:

```python
import asyncio, os
from tripo3d import TripoClient, TaskStatus   # pip install tripo3d

async def main():
    async with TripoClient(api_key=os.environ["TRIPO_API_KEY"]) as client:
        # 1. Референс: локальный файл -> загрузка -> image_to_model
        task_id = await client.image_to_model(
            image="/Users/dmitrij/cockpit/refs/seat_front.jpg",
            texture_quality="high",
            face_limit=20000,
        )
        # 2. Статус: polling до завершения (task_id храните для правок)
        task = await client.wait_for_task(task_id, verbose=True)
        # 3. Файлы: GLB/FBX + превью в локальную папку
        if task.status == TaskStatus.SUCCESS:
            files = await client.download_task_models(task, "./out")
            print(files)

asyncio.run(main())
```

Для правок используется тот же паттерн, что и в моём плагине: последующие операции (retexture, decimate) принимают `task_id` предыдущей задачи вместо новой генерации с нуля. REST-вариант создания задачи: `POST /v2/openapi/task` с `"type": "image_to_model"` и Bearer-авторизацией.

## 4. Стоимость и как проверить до запуска

**Подтверждённых тарифов на agent-gw-генерацию нет** — это буквально предмет открытого issue #4429. Поэтому проверять там нечего.

По Tripo (вторичный источник, сверяйте с официальной страницей цен): кредитная модель — бесплатный план ~300 кредитов/мес, 1 параллельная задача; text-to-3D и image-to-3D ~30–50 кредитов, multiview ~60–80; Professional $15.90/мес за 3000 кредитов. Практический способ проверить стоимость до запуска: зарегистрироваться на platform.tripo3d.ai, посмотреть баланс кредитов в консоли, выполнить одну тестовую задачу на бесплатном плане и сверить списание — это и будет ваш верифицированный тариф.

## Вывод и рекомендуемая архитектура

Прямого программного канала «Codex → этот веб-агент» нет и внешним MCP его не сделать: MCP в Kimi Code — это клиентская сторона (CLI подключается к MCP-серверам), а не сервер, принимающий задания для веб-чата. Поддерживаемая схема, максимально близкая к вашей цели:

1. **Codex → Tripo API напрямую** (или через fal.ai) для 3D — полный цикл из протокола из прошлого ответа работает без изменений, статус через `task_id`, правки через операции по `task_id`.
2. **Генерация изображений** — либо остаётся ручной задачей веб-Kimi (я отрабатываю по заданию из общей папки, когда вы его ставите), либо подключается сторонний image API по вашему выбору.
3. Если хотите единый агентный слой — официальный **Kimi Agent SDK** на вашем Mac оркестрирует локальный Kimi Code, а генерацию выносите в отдельный локальный MCP-сервер, оборачивающий Tripo/другие API; тогда `kimi -p` сможет вызывать их как инструменты.

Если issue #4429 получит официальный ответ с документированной авторизацией agent-gw — появится и третий вариант; следить за ним можно прямо на GitHub.
