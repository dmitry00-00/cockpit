## Размеры и прозрачность
| Семейство | Ширины WebP, px |
|---|---|
| Портреты | 64 / 128 / 256 |
| Эмблемы и предметы | 48 / 96 / 192 |
| Приборы | 256 / 512 |
| Сцены | 320 / 640 / 960 |

Высота вычисляется из исходного соотношения сторон с округлением до пикселя. Маленький исходник не увеличивается, повторяющиеся размеры исключаются. Рецепт: libwebp cwebp, quality 82, method 6, alpha quality 100, exact, без метаданных. Для этой поставки использован cwebp 1.6.0. В реестре alpha означает фактический alpha-флаг закодированного файла, а не обещание удаления фона. Пробы БА9 непрозрачны; прозрачные новые ассеты поддержаны и проверены отдельной RGBA-фикстурой с обратным декодированием через dwebp.

68 WebP занимают **613 386 байт, 0.585 MiB** против **44.9 MiB** исходников. Это сумма всех размеров обоих направлений, не размер стартовой загрузки. Для каждого файла действует тестовый бюджет: до 64 KiB, сцены до 192 KiB. Компрессия не превращает живописную иллюстрацию в малый глиф: для 16/24/32px используется отдельный SVG/PNG-набор.

## Использование
`ArtImage` принимает типизированный id, обязательный alt, ширину и при необходимости sizes. Он задаёт srcset, width/height, пропорции, loading=lazy и decoding=async. Ошибка показывает доступный заполнитель; исходный PNG не скачивается как fallback. Смена id сбрасывает ошибку. Пустой alt остаётся декоративным и при ошибке.

Рамки, выделение, счётчики, фокус, hover и состояния принадлежат компонентам интерфейса. В файлы доставки они не дорисовываются. Художественные изображения не получают image-rendering:pixelated, в отличие от глифов.

На служебной странице «Токены» кнопка «Показать иллюстрации» загружает отдельный ArtSheet и реестр. До открытия нет img-элементов; после открытия 12 проб направления A. Самостоятельный стенд БА9 показывает оба направления через тот же реестр WebP; HTML-макет карточки тоже использует производный портрет. Пробы по-прежнему обозначены как концепты, не назначены реальным персонажам кампании.

## Сборка и проверка
- `npm run build:art` — проверка источников и кэша, производные, реестры и версионный атлас.
- `npm run build` — включает тему, глифы, ассеты, пакеты, TypeScript, Vite manifest и `check:art-delivery`.
- `npm run check:art-delivery` — проверяет уже созданный dist: файлы/хеши/размеры/alpha, атлас, отсутствие исходных PNG и ссылок на них в JS, отдельный ArtSheet вне графа статических импортов старта.
- `npm test` — включает подготовку реестров; тесты кэша и отказов, RGBA roundtrip, компонента и отложенного открытия. Проверка реального кодирования помечается skip только при отсутствии cwebp/dwebp; в текущей приёмке она выполнена, пропусков нет.

Для неизменённых источников кодировщик не нужен: в проект поставляются производные и их кэш, повторная сборка идемпотентна. Для добавления/изменения растров нужен локальный cwebp из libwebp. Если его нет, сборка сообщает об этом; ничего не скачивает и не заменяет качество молча. Для новых материалов сначала фиксируются источник, размеры, SHA256, промпт/происхождение и результат review в исходном manifest.

Повреждённая производная пересчитывается из проверенного оригинала. Оригинал с неожиданным SHA/размером останавливает сборку до замены реестра. Временный файл удаляется и при ошибке кодировщика. Старые версии автоматически не удаляются; очистка возможна после проверки отсутствия ссылок на них.
