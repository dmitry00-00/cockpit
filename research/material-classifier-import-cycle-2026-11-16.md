# Цикл «парсер → оценка материала»

**Срез:** 16.11.2026. Это интеграционный слой для локального импорта материалов; он не утверждает игровую механику и не активирует записи.

## Цикл

1. Существующий парсер разбирает JSON, Foundry, 5etools, Universal VTT или MapTool в `ImportCandidate`.
2. Общий этап `classifyParsedMaterials` собирает только текстовые поля как временные source-located spans (`/data/...`, JSON Pointer), вместе с ID кандидата, SHA-256 fingerprint, форматом, именем файла, редакцией и заявленной лицензией. Источник помечен `localOnly`.
3. Если локальный `MaterialClassificationProvider` подключён, он может вернуть черновой kind (`mechanic`, `fragment`, `nonmechanic`, `ambiguous`), примитивы, точные цитаты, unknowns, confidence, модель, параметры запуска, время и версию prompt; сырой ответ сохраняется рядом.
4. Валидатор отвергает чужой/изменённый fingerprint, неизвестные теги, отсутствие доказательства для метки и цитату, которая не является точной подстрокой указанного source span. Принятый результат остаётся `pending-review`.
5. Предложение импорта остаётся во «Входящих»; принятие добавляет только каталоговую запись с assessment. Это не одобрение классификации и не игровая активация.

## Текущее ограничение

Клиент локальной модели для приложения пока не подключён. Сейчас парсер готовит статус `awaiting-classifier` или `no-evidence`, а сам смысловой draft может быть добавлен через типизированный provider. Провайдер обязан явно обозначить `locality: 'local'`; импортируемый текст нельзя отправлять облачной модели. `no-evidence` означает, что парсер не нашёл текстовых полей в переданной записи, а не что в исходном материале нет механики.

Если текстовых фрагментов слишком много, вход модели ограничивается первыми 100 фрагментами / 24 000 символов, coverage отмечается `partial`; такую разметку нельзя распространять на весь материал.

## Границы проверки

- Классификатор использует девять тегов пилота: Ability, Effect, Resource, Constraint, Activation, Recovery, Progression, ChoiceSet, Resolution. Domain и Source остаются за рамками LLM-классификатора и заполняются отдельно.
- Exact-quote validation подтверждает, что цитата присутствует по указанному locator, но не доказывает правильность её смысла или выбранной метки.
- Источник, лицензия и редакция сохраняются из распарсенной записи, если они доступны. Наличие импортированного текста само по себе не подтверждает права.
- Входящие игрокам не показывают: статус и модельные заметки рендерятся только в панели мастера.

## Изменённые компоненты

- `src/import/materialClassification.ts` — извлечение source-located текста, provider contract, allowlist и проверка черновика.
- `src/rules/materials/classification.ts` — схема результата и словарь.
- `src/import/content.ts` и `src/import/mapTool.ts` остаются парсерами форматов; общий стык вызывается на границе импорта в `src/pages/DeskPage.tsx`.
- `src/engine/state.ts` сохраняет optional `materialAssessment` внутри принятой записи `ImportedContent`.

## Проверка и незавершённое

- Strict typecheck классификатора и его тестовой спецификации прошёл.
- Полный `npx tsc --noEmit -p tsconfig.app.json` пока блокируется тремя ошибками в `src/engine/reduce.ts` и `src/pages/desk/helpers.ts` по A5E Prestige; новые ошибки в импорте/панели не появились.
- Vitest для этой спецификации не запускался: в этой рабочей копии предыдущие целевые попытки зависали на `RUN` до начала кейсов.
- Браузерная приёмка не выполнена: `npm run dev` запускает генераторы темы/иконок/арта, затем Vite завершается с `listen EPERM` на `127.0.0.1:5180`. В рабочем дереве `design/tokens.css` и `design/tokens.json` были изменены ещё до этой проверки; их не откатывал.
- Автоматический локальный inference отсутствует. Этот срез соединяет parser-stage с typed classifier contract и inbox review; подключение provider — следующий шаг.
